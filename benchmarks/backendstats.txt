================================================================================
 1. PURPOSE
================================================================================
    Wall-clock timings for the LLVM backend lowering the self-host compiler's
    MLIR to a native executable. Tracks the multi-round backend perf effort:
    parallel-opt partitioning, serial-floor pipelining, lazy split, and the
    round-4 serial-spine + function-parallel EcoToLLVM work.

    Reference points:
      * Whole-module -O2 backend baseline (pre-parallel work): ~65.8 s LLVM
        backend / ~86.5 s total wall  (see 2026-07-06 parallel-opt tiers).
      * Round-4 dev-mode baseline (M0): 28.95 s wall (post serial-floor + lazy
        split; the starting point for the M1-M7 serial-spine milestones).

================================================================================
 2. HOW TO DO A TIMING RUN
================================================================================
Machine of record:  24 cores, 15 GB RAM (Linux 6.12).
Input:    build/compiler/build-kernel/bin/eco-compiler.mlir  (~85k LLVM fns).
Binary:   build/runtime/src/codegen/eco-boot-native  (RelWithDebInfo, LLVM 21.1.8).

--------------------------------------------------------------------------------
 COMPILE-TIME (backend lowering) — primary measurement
--------------------------------------------------------------------------------
  B=build/runtime/src/codegen/eco-boot-native
  IN=build/compiler/build-kernel/bin/eco-compiler.mlir
  /usr/bin/time -v $B --lowering-stats -O 2 [--parallel-opt=dev|cgu] -o /tmp/o.exe $IN

  * --lowering-stats prints the per-phase sub-timings (MLIR pipeline, MLIR->LLVM
    translation, cheap-IPO prologue, parallel opt+emit drain, externalize +
    serialize, link, ...). Use the 3-run median of "Elapsed (wall clock) time".
  * Modes:  none = whole-module -O2;  dev = no per-partition inlining;
            cgu = per-partition full -O2.
  * Round-4 sub-phase attribution uses ECO_ECO2LLVM_STATS=1 (EcoToLLVM stage
    timers) and --parallel-opt=dev unless noted.

--------------------------------------------------------------------------------
 RECURSIVE-TAX (produced-binary quality) — clean env
--------------------------------------------------------------------------------
 Build the compiler under each mode, then time it AS a compiler doing the
 Stage-7a self-compile (frontend only, --output=*.mlir). Clean env
 (rm -rf build ~/.eco; cmake --preset build). 234-module cold compile, fresh
 --builddir per run, /usr/bin/time -v user time, 99% CPU.

  # build eco-{none,dev,cgu}:
  $B [--parallel-opt=MODE] $IN -o /tmp/eco-MODE
  # then in build/compiler/build-kernel:
  /usr/bin/time -v /tmp/eco-MODE make --optimize --kernel-package eco/compiler \
     --local-package eco/kernel=/work/eco-kernel-cpp --builddir bdX \
     --output=bin/x.mlir /work/compiler/src/Terminal/Main.elm

 Gate: recursive tax must be <=3% (a faster backend that produces a slower
 compiler binary is a net loss on every subsequent frontend compile).

--------------------------------------------------------------------------------
 GOTCHA — regenerating the input .mlir
--------------------------------------------------------------------------------
  The `full` target runs `clean`, which wipes eco-compiler.mlir (it is a
  CUSTOM_COMMAND, not in `all`). Regenerate with:
      ninja -C build compiler/build-kernel/bin/eco-compiler.mlir

 2026-07-06 — Parallel-opt tiers (plans/parallel-llvm-opt-partitioning.md)
--------------------------------------------------------------------------------
Description: Replace serial whole-module -O2 with a cheap whole-module IPO
             prologue (IPSCCP/GlobalOpt/GlobalDCE) + per-partition opt on the
             emission threads. Two tiers: dev (no per-partition inlining) and cgu
             (per-partition full -O2).

Raw output — Compile-time (self-host mlir -> native exe, -O 2):
  mode                       LLVM backend   total wall   CPU
  default (whole-module -O2)   65.8 s        86.5 s      180%
  --parallel-opt=dev           28.7 s        49.0 s      281%
  --parallel-opt=cgu           31.4 s        53.4 s      303%
  Backend speedup: dev 2.30x, cgu 2.09x.  Total: dev 1.77x, cgu 1.62x.

  The serial whole-module -O2 (~51 s @ 107% CPU) is replaced by a cheap
  whole-module IPO prologue + per-partition opt. Confirms the inliner+fused-
  simplification was the bulk.

 2026-07-07 — Round 4: function-parallel EcoToLLVM (plans/eco-to-llvm-parallel-conversion.md)
--------------------------------------------------------------------------------
Description: Parallelize the M7-identified dominant phase (applyFullConversion,
             89.7% of EcoToLLVM). Env-gated ECO_ECO2LLVM_PARALLEL (default serial).

PHASE 1 (serial signature/body split) — DONE + VALIDATED:
   Restructured EcoToLLVMPass::runOnOperation into Stage 0 (module-anchored:
   func-signature conversion + kernel decls + module globals) and Stage 2
   (per-llvm.func serial loop with the original body target/patterns). Two bugs
   found+fixed via deterministic ecoc repro (CombinatorTest.mlir) + IR diff:
     (1) symCache staleness: clear after Stage 0 op-replace.
     (2) typedNewargs shell-sensitivity: only run the args-array check when target
         is NOT in origFuncTypes (else 15 typed wrappers dropped -> SIGSEGV).
   Validation: codegen 376 + E2E 226->2 (2 flaky, pass standalone); self-host
   functional core BYTE-IDENTICAL. Stage breakdown (ECO_ECO2LLVM_STATS):
     Stage0 806ms (serial) | Stage2 4951ms (78%, PARALLELIZABLE) |
     GC-walk 293 | rootInit 270 | pre-scan+allocGroups 52.
   NOTE: serial split adds ~1.5s overhead vs the 4906ms single conversion
   (per-function applyFullConversion setup x85k). Parallel must beat that.

PHASE 2 (pre-materialize + parallel) — DONE + VALIDATED. IT SCALES.
   Design (Option B): make symCache READ-ONLY during Stage 2 so lookupSymbol is
   LOCK-FREE, then run per-function body conversion in parallel. Serial priming:
   materializeAllRuntimeDecls pre-declares ALL ~135 runtime externs (unused ones
   stripped after Stage 2 via SymbolUserMap); string-literal + string-case
   globals via Operation*->index side maps; closure wrappers via getOrCreateWrapper
   walk. Eval-layouts moved OUT of symCache into a dedicated DenseSet + std::mutex.
   Stage 2 driver: chunked mlir::failableParallelForEach, N=maxConcurrency chunks,
   each chunk builds its OWN EcoTypeConverter+FrozenRewritePatternSet+
   ConversionTarget+EcoCFContext.
   MEASURED (self-host, 24-core, isolated, ECO_ECO2LLVM_STATS):
     Stage 2 body conversion:  4376 ms  ->  737 ms   (5.9x)
     MLIR lowering pipeline:   11.89 s  ->  8.02 s
     wall:                     27.27 s  ->  23.81 s   (-3.46s serial-vs-parallel)
     CPU:                      466%     ->  557%
     NET vs round-4 baseline (single conversion 26.4s): -> 23.81s = -2.6s (-9.8%)
       (split+pre-mat+strip infra adds ~0.9s serial; parallelism removes ~3.6s.)
   CORRECTNESS: serial codegen 376; parallel closure repros exit 0; PARALLEL
     self-host binary FUNCTIONAL CORE BYTE-IDENTICAL to serial.
   BUGS FOUND+FIXED (each via deterministic ecoc repro + IR diff):
     (1) symCache staleness after Stage 0 op-replace; (2) typedNewargs shell-
     sensitivity dropping 15 typed wrappers; (3) dead-decl strip was O(decls x
     module) = 213s (symbolKnownUseEmpty -> SymbolUserMap, once); (4) parallel
     driver was initially not wired (Stage 2 left as serial loop).
   VERDICT: function-parallel EcoToLLVM is a REAL WIN (~-2.6s / -10% wall),
     contradicting the design doc's "blocked / not-a-win" prior. Kept ENV-GATED
     (default serial) pending broader validation before default-on: full E2E in
     parallel mode + ECO_HEAP_VALIDATE GC-stress + self-host byte-identity across
     none/dev/cgu (the parked-EcoTailConversions Heisenbug family warrants it).
   FOLLOW-UP OPT: the ~2s SymbolUserMap strip is pure overhead on the production
     path (backend internalize+GlobalDCE drops the unused externs anyway); gate
     it to a test/dump mode to recover ~2s and push the net win toward -4.6s.

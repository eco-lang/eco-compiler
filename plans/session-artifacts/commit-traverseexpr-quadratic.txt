Apply traverseExpr's callback once per node instead of once per let/case path

MonoTraverse.traverseExpr passed the already-lifted `traverseExpr f` to traverseExprChildren, which
applied it directly to call, list, if and closure children but handed it to traverseDef,
traverseDecider and traverseChoice for let RHSs and case branches - and those lifted it AGAIN. Every
let-RHS and case-branch subtree was therefore walked by `traverseExpr (traverseExpr f)`: each of its
nodes re-walked its own subtree, and every nested let/case inside repeated the trick, so the cost
was exponential in let/case nesting depth and the callback ran once per path rather than once per
node. On the Sep-3 self-compile this was 2.27e9 callback calls over a 190K-node tree.

Make traverseExprChildren and the def/decider/choice helpers all take the user callback and recurse
through `traverseExpr f` as a saturated direct call, so there is exactly one lift, one visit per
node (children first, evaluation order) and no `traverseExpr f` PAP built per node. Replace
traverseList with typed helpers (traverseExprs, traverseKeyed, traverseCaptures, traverseBranches,
traverseEdges) for the same reason. The fold family already lifted once and is untouched.

Add MonoTraverseTest pinning visits == nodes over 12-deep let and 10-deep case chains, evaluation
order, and identity. Self-compile output stays byte-identical; E2E 1718/1718; fixed point holds.

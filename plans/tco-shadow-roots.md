# TCO-Safe Shadow Root Frames for `func.func` Arguments

## Problem

Functions that own long-lived GC-managed values can lose track of those values
when downstream LLVM passes (sibling-call TCO, `RewriteStatepointsForGC`) DCE
`gc.relocate` results or elide caller frames. The canonical symptom is the
`ListReverseStressTest` failure: `main_$_0` binds `start : List Int`, calls
`reverseNTimes start`, which tail-recurses 1000 times with small nursery GCs
in between. By the time control returns to `main_$_0` and uses `start` again,
the SSA value still holds the pre-GC HPointer for `start`, because:

1. The `gc.relocate` results generated by `RewriteStatepointsForGC` for `start`
   across `reverseNTimes` are unused except for later uses of `start` that end
   up folded away; DCE drops the relocates.
2. Without a `gc.relocate`, the statepoint has no way to update `start` in
   `main_$_0`'s SSA across the callee-triggered GC.

The problematic optimization is **LLVM's sibling-call elimination on
`gc.statepoint` results**, not Eco's joinpoint→`scf.while` transformation.
Eco-level TCO already loops in MLIR and is safe; this design hardens the IR
against LLVM's TCO when LLVM still sees tail-position calls.

The fix used for closure arg arrays already (EcoToLLVMClosures.cpp —
`emitPushArgsRootRange` / `emitRestoreArgsRootRange`) is to park HPointers in
an alloca'd `i64` array that is registered with the runtime via
`eco_gc_push_stack_range`. The collector relocates the array slots in place,
and the escape of the alloca address to a runtime call forces LLVM to reload
the slot after every call.

We apply the same technique to selected `func.func` bodies so they become
independent of LLVM's statepoint/TCO interactions. This is a compile-time,
per-function, opt-in mechanism.

## Goal

For a `func.func` marked with `eco.shadow_roots`:

- On entry: allocate a stack array `[N x i64]` for each `!eco.value` parameter,
  store each parameter's HPointer into its slot, register the array with the
  runtime via `eco_gc_stack_range_point` / `eco_gc_push_stack_range`.
- On every use of one of those parameters: go through a `loadValueFromShadowSlot`
  helper that emits `load i64 + inttoptr i64 to ptr addrspace(1)` immediately
  before the use (REP_LLVM_001).
- On every exit path: call `eco_gc_restore_stack_range_point(saved)`.
- Do **not** alter `EcoGCPrepare`, `RewriteStatepointsForGC`, or stackmap
  parsing. The range is GC-visible because `RootSet::stack_root_ranges` is
  already scanned by the collector each cycle.

## Non-goals

- No new GC root data structure. `StackRootRange` and its three C helpers
  already exist (RootSet.hpp:75–97, RuntimeExports.h:355–360).
- No Eco dialect change. `eco.shadow_roots` is a dictionary attribute on
  `func.func`; no op/type changes.
- Phase 1 does not narrow rooting to "live-across-safepoint" args. It roots
  **every `!eco.value` parameter** of marked functions, which is a conservative
  superset that is always correct. Narrowing via `mlir::Liveness` is Phase 3.
- Phase 1 does not root locals. The motivating class of failures is about
  top-entrypoint parameters held across many GCs in callees; no known case
  exists of a non-parameter local becoming stale solely because a caller
  frame was sibling-eliminated. Lifting this restriction is deferred until
  such a case appears.
- Phase 1 does not auto-pick which functions get marked. Marking is manual,
  attached to `main_$_0` only by a targeted patch in the Elm compiler or by
  hand-editing `.mlir` for tests.

## Structural decision — where the transform lives

The original sketch proposed modifying `FuncOpLowering` in `EcoToLLVMFunc.cpp`.
That file currently only defines `KernelFuncOpLowering`, which matches
`is_kernel` external decls. Regular Elm `func.func` ops are lowered by MLIR's
built-in `populateFuncToLLVMConversionPatterns` (EcoToLLVM.cpp:279), which we
don't own.

The transform reads `eco.shadow_roots` **off the `func::FuncOp` directly**
(before it is erased during conversion), so there is no need to copy attributes
to `LLVM::LLVMFuncOp`. The cleanest placement, consistent with the existing
house-style post-conversion walks in `EcoToLLVMPass::runOnOperation` (the
`setGarbageCollector("eco-gc")` walk at EcoToLLVM.cpp:354 and the pre-conversion
`origFuncTypes` walk at EcoToLLVM.cpp:250), is:

1. **Pre-conversion walk** inside `EcoToLLVMPass::runOnOperation`: collect the
   names of `func::FuncOp`s that carry `eco.shadow_roots` into a
   `DenseSet<StringRef>` kept alongside `origFuncTypes`.
2. **Post-conversion walk** in the same pass, after `applyFullConversion`:
   for each `LLVM::LLVMFuncOp` whose symbol name is in that set, install the
   shadow-root frame (prologue, use-rewrites, epilogues).

Running post-conversion means args are already `ptr addrspace(1)` and we emit
pure LLVM dialect — no dialect-conversion interaction, no attribute copying,
no reimplementation of MLIR's func-to-llvm conversion. The logic lives in
`EcoToLLVMFunc.cpp` so all per-function setup stays in one file.

## Plan

### Step 1 — Attribute convention

Use an MLIR unit attribute on `func.func`:

```mlir
func.func @main_$_0(%arg0: !eco.value) attributes { eco.shadow_roots } {
  ...
}
```

No TableGen or dialect change. For Phase 1 the Elm compiler attaches this
attribute only to the top-level `main_$_0` entrypoint; other entrypoints
(platform runtime main, scheduler entry) remain unmarked until measured.

### Step 2 — Pre-conversion collection

In `EcoToLLVMPass::runOnOperation`, extend the existing pre-conversion walk:

```cpp
DenseSet<StringRef> shadowRootFuncs;
module.walk([&](func::FuncOp funcOp) {
    runtime.origFuncTypes[funcOp.getSymName()] = funcOp.getFunctionType();
    if (funcOp->hasAttr("eco.shadow_roots"))
        shadowRootFuncs.insert(funcOp.getSymName());
});
```

Reading the attribute off `func::FuncOp` sidesteps the question of whether
`populateFuncToLLVMConversionPatterns` preserves it on `LLVM::LLVMFuncOp`.

### Step 3 — Internal helpers in `EcoToLLVMInternal.h`

Add, alongside the existing value-conversion helpers (EcoToLLVMInternal.h:55):

```cpp
struct ShadowRootFrame {
    mlir::Value savedPoint;           // i64 returned by eco_gc_stack_range_point
    mlir::Value basePtr;              // i64*, points to roots[0]
    llvm::DenseMap<mlir::BlockArgument, mlir::Value> slotForArg;  // arg -> i64* slot
};

ShadowRootFrame installShadowRootPrologue(
    mlir::LLVM::LLVMFuncOp func,
    mlir::OpBuilder &builder,
    const EcoRuntime &runtime);

mlir::Value loadValueFromShadowSlot(
    const ShadowRootFrame &frame,
    mlir::BlockArgument arg,
    mlir::OpBuilder &builder,
    mlir::Location loc);

void emitShadowRootEpilogues(
    const ShadowRootFrame &frame,
    mlir::LLVM::LLVMFuncOp func,
    const EcoRuntime &runtime);
```

Placement: these are function-scope helpers specific to `EcoToLLVMFunc.cpp`;
declaring them in `EcoToLLVMInternal.h` matches house style for shared
helpers (HPtr conversions, `EcoRuntime`, `EcoCFContext`).

### Step 4 — Prologue construction (`installShadowRootPrologue`)

Implemented in `EcoToLLVMFunc.cpp`:

1. Collect `SmallVector<BlockArgument> gcArgs` = all entry-block args of type
   `ptr addrspace(1)` (use `isHPtrLLVMType` from EcoToLLVMInternal.h:47). If
   empty, return an empty `ShadowRootFrame{nullptr, nullptr, {}}`.
2. In debug builds: `assert(gcArgs.size() <= 64 && "shadow root frame supports at most 64 slots")`.
   64 is far above any realistic Elm arity; release builds get no assert and
   will overflow the mask if violated, which is acceptable given the
   invariant.
3. Set the insertion point to the **start of the entry block**.
4. Emit:
   - `LLVM::AllocaOp` for element type `i64`, count `N` (matches the arg-array
     convention at EcoToLLVMClosures.cpp:106–107, giving a single `i64*` base).
   - `LLVM::MemsetOp` to zero `N*8` bytes (matches existing convention from
     stack-root-ranges-gc-fix.md: unregistered slots must be safe for GC).
   - `savedPoint = call @eco_gc_stack_range_point()` via
     `runtime.getOrCreateGcStackRangePoint(builder)` (EcoToLLVMInternal.h:307).
   - For each `gcArgs[i]`:
     - `slot = LLVM::GEPOp(basePtr, i)` giving an `i64*`.
     - `hp = LLVM::PtrToIntOp(arg, i64)`.
     - `LLVM::StoreOp(hp, slot)`.
     - Populate `slotForArg[arg] = slot`.
   - `call @eco_gc_push_stack_range(basePtr, N, mask)` with
     `mask = (1ULL << N) - 1` (all slots are HPointer; see RootSet.hpp:70–74
     for mask semantics).
5. Return the populated `ShadowRootFrame`.

### Step 5 — Rewrite uses via `loadValueFromShadowSlot`

For each rooted `BlockArgument arg` with slot `slotPtr`:

- Collect `arg.getUses()` into a SmallVector before mutating (operand
  rewriting invalidates use-iterators otherwise).
- For each use, set the insertion point to **immediately before the user op
  that contains the use**. For a terminator (`LLVM::BrOp`, `LLVM::CondBrOp`,
  `LLVM::SwitchOp`, `LLVM::ReturnOp`) whose operand is the rooted arg, that
  means "before the terminator in the same block" — no cross-block surgery.
- Emit `loadValueFromShadowSlot(frame, arg, builder, loc)`, which expands to:
  - `%hp = LLVM::LoadOp(slotPtr) : i64`
  - `%v  = LLVM::IntToPtrOp(%hp) : ptr<1>`
- `use.set(v)` to rewrite the specific use, leaving the SSA control-flow
  graph and branch structure intact.

This matches the house style of centralizing value conversions through
helpers (`valueToI64`, `i64ToValue` in EcoToLLVMInternal.h:55–75) rather
than inlining casts at each site.

Correctness guarantees:

- The alloca's address escapes to `eco_gc_push_stack_range`, so LLVM's alias
  analysis must treat all calls (including tail calls, statepoints) as
  potential clobbers. Loads we emit cannot be CSEd across a call.
- Even if LLVM CSEs two loads with no intervening call, both reads return the
  same value (GC runs only at safepoints, which live on calls), so the CSE is
  correctness-preserving.

### Step 6 — Epilogues on every exit (`emitShadowRootEpilogues`)

Walk `LLVM::ReturnOp` ops in the function. For each:

- Insert immediately before the return:
  `call @eco_gc_restore_stack_range_point(savedPoint)`.

`savedPoint` dominates all returns because the prologue runs at the start of
the entry block. `LLVM::UnreachableOp` does not need a restore.

### Step 7 — Driver wiring in `EcoToLLVMPass::runOnOperation`

After the existing `setGarbageCollector("eco-gc")` walk (EcoToLLVM.cpp:354),
add:

```cpp
module.walk([&](LLVM::LLVMFuncOp func) {
    if (func.isExternal()) return;
    if (!shadowRootFuncs.contains(func.getSymName())) return;
    OpBuilder builder(func.getContext());
    auto frame = installShadowRootPrologue(func, builder, runtime);
    if (frame.basePtr) {
        for (auto arg : frame.slotForArg.keys())
            rewriteUsesViaShadowSlot(frame, arg, builder);
        emitShadowRootEpilogues(frame, func, runtime);
    }
});
```

(`rewriteUsesViaShadowSlot` is the loop from Step 5, declared in
`EcoToLLVMInternal.h` as well.)

No pipeline change is required — we stay inside the existing `eco-to-llvm`
pass.

### Step 8 — Mark `main_$_0` in the Elm compiler

Phase 1 marking: in the Elm compiler's MLIR-gen, detect the top-level `main`
entrypoint (the function named `main_$_0`) and attach
`{ eco.shadow_roots }` to its emitted `func.func`. Scope restricted to
that one function; no heuristic for other entrypoints.

For rapid iteration before touching the Elm side, hand-patch the generated
`.mlir` for `ListReverseStressTest` as a one-shot to validate the runtime
behavior.

### Step 9 — Verification

- **MLIR-level FileCheck test**: new file
  `runtime/test/codegen/shadow_roots.mlir` that defines a function with
  `eco.shadow_roots` and a single `!eco.value` param, checking that the
  lowered LLVM dialect contains:
  - an `llvm.alloca` of `i64 x N`,
  - `memset` zeroing the array,
  - calls to `eco_gc_stack_range_point`, `eco_gc_push_stack_range`,
    `eco_gc_restore_stack_range_point`,
  - a `load + inttoptr` in place of direct uses of the arg.
- **E2E stress test**: run `ListReverseStressTest` with a small nursery via
  the existing stress knobs. Confirm the test passes only with `main_$_0`
  marked, then move the marking into the compiler and confirm it still
  passes.
- **Liveness audit**: with `ECO_GC_DEBUG_LIVENESS` on, confirm
  `EcoGCLivenessAudit` doesn't regress. The audit operates on `func::FuncOp`
  before EcoToLLVM, so the new transform runs entirely outside its purview.
- **Microbenchmark before expanding marking**: for Phase 1, `main_$_0` is
  not hot, so the extra load per use is negligible. Before Phase 2 marks
  hot-path functions, add a benchmark: a tight loop in a marked function
  with many uses of a rooted param, measure with/without the attribute, and
  use that to decide whether to expand marking or invest in Phase 3
  liveness-narrowing.

## What we do NOT change

- `RootSet`, `NurserySpace`, `OldGenSpace`, `ThreadLocalHeap`: no code change.
  Stack-range scanning already handles our new ranges.
- `RuntimeExports.h` / `RuntimeExports.cpp`: no new API. Optional one-line
  comment near `eco_gc_stack_range_*` noting EcoShadowRoots as a second
  consumer.
- `EcoGCPrepare` and `EcoGCLivenessAudit`: untouched.
- `EcoToLLVMClosures.cpp`: unchanged. Existing closure arg-array logic is
  orthogonal.
- `EcoPipeline.cpp`: no new pass added; the transform lives in the existing
  `eco-to-llvm` pass.

## Rollout phases

- **Phase 1 (this plan)**: opt-in attribute, conservative (root every
  `!eco.value` param), mark `main_$_0` only, verify on `ListReverseStressTest`.
- **Phase 2 (follow-up, separate plan)**: after microbenchmarking, extend
  marking to other long-lived entrypoints if needed (platform runtime main,
  scheduler entry functions) — only if concrete failures or measurable risk
  are observed there.
- **Phase 3 (follow-up, separate plan)**: narrow the rooted set to only args
  live across a potential safepoint using `mlir::Liveness` on `func.func`
  before EcoToLLVM, stashing the per-arg decision into the driver-side set
  consumed by the post-conversion walk.

## Resolved questions (was: open questions)

1. **Attribute preservation.** Resolved: read `eco.shadow_roots` off
   `func::FuncOp` in the pre-conversion walk, so nothing needs to survive
   the func-to-llvm conversion.
2. **Phase 1 scope.** Resolved: all `!eco.value` params of marked functions,
   no liveness narrowing.
3. **Which functions to mark.** Resolved: `main_$_0` only for Phase 1;
   scheduler / platform runtime entry points deferred to Phase 2 after
   measurement.
4. **Locals vs. parameters.** Resolved: parameters only in Phase 1. No
   concrete non-parameter-local case is known. Lifting this restriction is
   deferred until such a case appears.
5. **Eco-level vs. LLVM-level TCO.** Resolved: the target is LLVM
   sibling-call elimination on `gc.statepoint` results, not Eco's
   joinpoint→`scf.while` transformation. The two are independent; this
   design is for robustness when LLVM still sees tail-position calls.
6. **Placement of the transform.** Resolved: inside `EcoToLLVMPass`
   (pre-conversion walk collects names, post-conversion walk applies the
   frame). Per-function setup stays in `EcoToLLVMFunc.cpp`. No separate pass,
   no reimplementation of MLIR's func-to-llvm conversion.
7. **Phi / branch operand rewriting.** Resolved: use `loadValueFromShadowSlot`
   as a per-use helper. For terminator operands, insert the load before the
   terminator in the same block and rewrite the specific use — the SSA graph
   and branch structure stay intact; no pred-block surgery, no phi rewriting.
8. **Debug assertion for `count > 64`.** Resolved: `assert(N <= 64, ...)` in
   the prologue. Realistic Elm arities are far below; the assert only fires
   on a bug.
9. **Overhead.** Resolved: acceptable for Phase 1 (`main_$_0` is not hot).
   Add a microbenchmark before Phase 2 expands marking into hot paths.

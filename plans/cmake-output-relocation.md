# Relocate Compiler & Test Outputs Under `${CMAKE_BINARY_DIR}`

## Goal

Move every build-produced file currently written into the source tree under the CMake binary directory (`build/`, `debug/`, or `build-profile/`), so that:

- `rm -rf build/` resets everything the build system produces.
- The source tree stays clean: no more `eco-stuff/`, `elm-stuff/`, `bin/` clutter under `compiler/build-{xhr,kernel}/` or `test/<pkg>/`.
- `compiler/build-xhr/` and `compiler/build-kernel/` disappear from source entirely.
- The long `ADDITIONAL_CLEAN_FILES` list in `CMakeLists.txt:103–126` and the bespoke `rm -rf` recipes in the `rebuild`/`full` targets (CMakeLists.txt:130–193) go away.
- Switching between CMake configurations (release vs debug) gives each its own isolated bootstrap cache — desirable, since different `-O`/assertion settings can legitimately produce different MLIR.

## Strategy: shadow elm.json files in the build tree

Both `eco-stuff/` and `elm-stuff/` are anchored by the compiler (and stock Elm) walking up from cwd looking for `elm.json`. We don't modify the compiler. We just have CMake's configure step materialize an elm.json (plus its sibling config files) under `${CMAKE_BINARY_DIR}` and symlink `src/` from there back at the real source. `eco-stuff/` and `elm-stuff/` then land in the build tree automatically.

IDE coverage for the compiler is already provided by `compiler/elm.json` (application, source-directories `["src", "src-xhr"]`); we don't need a separate IDE-visible template under `compiler/build-xhr/`. Each test package keeps its own `test/<pkg>/elm.json` in source as both the IDE-visible elm.json and the input CMake reads to produce the shadow.

## Resolutions

| Question | Decision |
|---|---|
| Phasing | Single PR — compiler, tests, and docs together. |
| IDE templates under `compiler/build-{xhr,kernel}/` | Don't keep — `compiler/elm.json` already covers the IDE; delete both source-tree dirs. |
| `compiler/scripts/build*.sh` | Keep on disk for now, but they have no functional role in CMake. May or may not work standalone after the move. |
| Build-tree shadow layout | Mirror source: `${CMAKE_BINARY_DIR}/compiler/build-xhr/`, `${CMAKE_BINARY_DIR}/compiler/build-kernel/`, `${CMAKE_BINARY_DIR}/test/<pkg>/`. |
| `source-directories` form | Symlinks. Each shadow contains a `src` symlink (and `src-xhr`/`tests`/`src-kernel` as needed) pointing back at source; elm.json's `source-directories` stays `["src"]` etc. |
| Per-config cache separation | Acceptable, desirable. |
| `compiler/examples/` | No shadow; leave source-tree. Drop only its `ADDITIONAL_CLEAN_FILES` entry. |
| `elm-test-rs --project build-xhr` | Update `compiler/package.json` to point at the build tree (e.g. `--project ../build/compiler/build-xhr`). |
| `mlir-equivalence` per-test scratch | Auto-follows test-package shadowing — no extra work. |
| CI cache | No CI yet; not a concern. |

## Implementation steps (single phase)

### 1. Extract the compiler bootstrap templates

Move the input templates that currently live under `compiler/build-{xhr,kernel}/` to a clear template location. Proposed: `compiler/cmake/bootstrap/` with one subdirectory per shadow root.

- `compiler/cmake/bootstrap/build-xhr/elm.json` (current contents of `compiler/build-xhr/elm.json`).
- `compiler/cmake/bootstrap/build-kernel/elm.json` (current contents of `compiler/build-kernel/elm.json`).
- `compiler/cmake/bootstrap/build-kernel/heap-config.json`, `inject-bytecode-monitor.js`, `inject-mem.js`, `run-eol2.js`.

Alternative: embed the elm.json content directly in `compiler/CMakeLists.txt` via `file(WRITE)`. Reject this — the dependency lists are ~30 lines each and read better as JSON.

Note: the source-directories field in the extracted elm.json files becomes `["src", "src-xhr"]` and `["src"]` respectively (was `["../src", "../src-xhr"]` and `["../src"]`), because the shadow will materialize `src` as a symlink.

### 2. Add shadow-generation logic in `compiler/CMakeLists.txt`

At configure time:
- `file(COPY ...)` the templates into `${CMAKE_BINARY_DIR}/compiler/build-{xhr,kernel}/`.
- `file(CREATE_LINK ... SYMBOLIC)` for `src`, `src-xhr`, `tests`, `src-kernel`.
- `configure_file(... COPYONLY)` for `elm-application.json` from `${CMAKE_SOURCE_DIR}/compiler/`.

### 3. Repoint path variables in `compiler/CMakeLists.txt`

- `set(BUILD_XHR_DIR "${COMPILER_DIR}/build-xhr")` → `set(BUILD_XHR_DIR "${CMAKE_BINARY_DIR}/compiler/build-xhr")`.
- Same for `BUILD_KERNEL_DIR`.
- Every `add_custom_command`'s `WORKING_DIRECTORY` and `--output=` already references these variables, so the rest cascades.
- Drop `${BUILD_XHR_DIR}/bin/`, `${BUILD_KERNEL_DIR}/bin/`, `${BUILD_XHR_DIR}/elm-stuff/`, `${BUILD_KERNEL_DIR}/elm-stuff/` and the `${BUILD_KERNEL_DIR}/eco-stuff/` entries from the `ADDITIONAL_CLEAN_FILES` block at `compiler/CMakeLists.txt:288–294` — they're inside `${CMAKE_BINARY_DIR}` now.

### 4. Add test-package shadow generation in `test/CMakeLists.txt`

For each of the 11 packages:
- `file(COPY ${CMAKE_SOURCE_DIR}/test/<pkg>/elm.json DESTINATION ${CMAKE_BINARY_DIR}/test/<pkg>/)`.
- `file(CREATE_LINK ${CMAKE_SOURCE_DIR}/test/<pkg>/src ${CMAKE_BINARY_DIR}/test/<pkg>/src SYMBOLIC)`.

Drive this from a single CMake `foreach()` over a list of package names.

### 5. Update the test harness lookup logic

- `test/ElmE2ETestBase.hpp::findTestDir` (line 1089–1103): replace the source-tree candidate list (`test/<name>`, `../test/<name>`, `../../test/<name>`) with `${BUILD_DIR}/test/<name>`, where `BUILD_DIR` is plumbed in the same way `REPO_ROOT` is at `test/CMakeLists.txt:96` — add `target_compile_definitions(test PRIVATE BUILD_DIR="${CMAKE_BINARY_DIR}")` for `test`, `stress-test`, and `mlir-equivalence`.
- `test/mlir_equivalence_main.cpp::test_package_dirs()` (lines 178–192): swap `REPO_ROOT "/test/<pkg>"` for `BUILD_DIR "/test/<pkg>"`. `mlir-equivalence-out/` already lives under `${CMAKE_BINARY_DIR}` (line 458) and stays put.

### 6. Strip clean-list bloat from the top-level `CMakeLists.txt`

- Delete the per-test-package `ADDITIONAL_CLEAN_FILES` and `ADDITIONAL_MAKE_CLEAN_FILES` blocks (`CMakeLists.txt:103–126`) — outputs are now under `${CMAKE_BINARY_DIR}`.
- Delete the `rm -rf` prefix recipes from the `rebuild`, `full`, and `stress` custom targets (`CMakeLists.txt:130–193`). The targets reduce to `cmake --build` + `${CMAKE_BINARY_DIR}/test/test`.
- Keep the `compiler/examples/eco-stuff` line if you want CMake to still clean it; otherwise drop. Per resolution: leave examples source-tree, drop the entry.

### 7. Update `compiler/package.json`

`"test": "elm-test-rs --project build-xhr --fuzz 10"` → `"test": "elm-test-rs --project ../build/compiler/build-xhr --fuzz 10"`.

Caveat: this assumes the `build/` preset has been configured. If users routinely run `npm test` without a CMake build, document the prerequisite.

### 8. Update shell wrappers

`compiler/scripts/build.sh`, `build-self.sh`, `build-verify.sh`: leave on disk but they no longer participate in CMake. If we want them to remain runnable standalone, update their `BUILD_XHR_DIR`/`BUILD_KERNEL_DIR` defaults to point at `${CMAKE_BINARY_DIR}/compiler/build-{xhr,kernel}/` (with an env-var override) — but this is optional since CMake targets cover the same flows.

### 9. Update `compiler/.gitignore`

Remove the now-irrelevant entries (`build-xhr/bin/`, `build-xhr/elm-stuff/`, `build-kernel/bin/`, `build-kernel/elm-stuff/`, `eco-stuff/`). The corresponding directories no longer exist.

### 10. Update docs and memories

- 12 guide files in `/work/guides/`: `bootstrap.md`, `cpp-prof-fix-loop.md`, `cpp-profiling-howto.md`, `cpp-prof-hints.md`, `dce-fix-loop.md`, `eol2-howto.md`, `gc-diagnostics.md`, `mem-profiling-howto.md`, `perf-profiling.md`, `stack-fix-loop.md`, `test-coverage-howto.md`, `test-fix-loop.md`.
- `/work/CLAUDE.md` and `/work/Readme.md` (both reference `--project build-xhr`).
- Serena memories that embed the old paths: `elm_doc_preview_workflow.md`, `nodejs_profiling_tips.md`, possibly `suggested_commands.md`.

Search-and-replace `compiler/build-xhr` → `build/compiler/build-xhr` and `compiler/build-kernel` → `build/compiler/build-kernel`, then read each diff to make sure the rewrites make sense in context (some references are to `cd compiler/build-kernel`, others to `compiler/build-kernel/bin/eco-compiler`, etc.).

### 11. Delete the source-tree directories

After steps 1–10 are in place, `git rm -r compiler/build-xhr compiler/build-kernel`. Verify nothing else references the old paths.

## Acceptance checks

- `cmake --preset ninja-clang-lld-linux && cmake --build build && cmake --build build --target full` succeeds; `git status` is clean afterwards.
- `rm -rf build/ && cmake --preset ninja-clang-lld-linux && cmake --build build` completes a full bootstrap (Stage 1 → Stage 8 if exercised) without writing under `compiler/` (anywhere) or `test/<pkg>/`.
- `cmake --build build --target check`, `stress`, and `run-mlir-equivalence` all still pass.
- `find compiler test -name eco-stuff -o -name elm-stuff -o -name 'build-xhr' -o -name 'build-kernel' 2>/dev/null` returns nothing (or only matches under `build/`).
- `compiler/.gitignore` is shorter; no source-tree `eco-stuff` patterns remain.
- `cd compiler && npm test` works (after `cmake --preset` has been run at least once).
- Switching from `build/` to `debug/` preset and back rebuilds the bootstrap independently in each tree — no cross-config contamination.
